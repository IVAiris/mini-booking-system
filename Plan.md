## 1.1 Целевой сценарий

Путь конечного пользователя данных этого цикла (проверяется без UI — через Server Actions/скрипт локальной проверки, аналогично тому, как auth-lite Шаг 6 проверялся через `curl` до появления полноценного UI):

1. В БД существует доступный `Slot` (создан вручную/через seed для локальной проверки).
2. `user` создаёт `Booking` на этот слот → бронь получает статус `pending`; слот перестаёт быть доступен для новой брони.
3. Владелец брони (`user`) получает `Notification` о создании брони.
4. `admin`/`super_admin` подтверждает бронь (`pending → confirmed`) → владелец получает `Notification` о подтверждении.
5. `admin`/`super_admin` отменяет подтверждённую бронь (`confirmed → cancelled`) → владелец получает `Notification` об отмене; слот снова доступен для новой брони.
6. Повторная попытка создать бронь на уже занятый (`pending`/`confirmed`) слот отклоняется сервером.
7. Попытка `user` отменить или подтвердить чужую бронь отклоняется сервером.
8. Попытка `user` подтвердить свою же бронь (роль `user`, не `admin`) отклоняется сервером.
