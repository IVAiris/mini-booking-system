Пользователь должен пройти один минимальный маршрут:

5. Открыть формы регистрации и входа как `guest`.
6. Зарегистрировать пользователя с ролью `user`.
7. Сохранить только `passwordHash`, созданный через `bcryptjs.hash(password, 12)`.
8. Войти через проверку `bcryptjs.compare(inputPassword, user.passwordHash)`.
9. Попасть в аккаунт только после серверной проверки сессии.
10. Проверить, что `seed`-пользователь с ролью `super_admin` проходит серверную проверку роли наравне с `admin`.
11. Обновить финальный `README.md` с командами запуска и smoke-тест.

## 2. Требования к результату

Сводка из `spec.md` (разделы «Цели», «Функциональные требования», «Критерии успеха»):

- Публичная регистрация создаёт аккаунт строго с ролью `user`; поле `role` из запроса игнорируется сервером.
- Пароль хранится только как bcryptjs-хеш (12 раундов), исходное значение нигде не сохраняется и не логируется.
- Вход по email/паролю создаёт серверную сессию (запись `Session` + cookie); выход инвалидирует сессию.
- Сообщение об ошибке валидации email — точная формулировка «Введите корректный адрес электронной почты».
- Страница `/account` доступна только авторизованному владельцу, показывает профиль, роль и карточки «Быстрые действия», зависящие от роли.
- Серверные проверки роли (`requireRole()`) обязательны для защищённых маршрутов — не полагаться на скрытие UI.
- Навигация показывает все пункты меню всегда, независимо от роли и статуса авторизации.
- Ровно один `super_admin` создаётся seed-скриптом; повторный запуск seed не создаёт дубликат; публичная регистрация не может создать `admin`/`super_admin`.
- Prisma и `@prisma/client` зафиксированы точной версией `6.19.3` (`--save-exact`).

## 5. Критерии готовности проекта

Сводка из `spec.md` (раздел «Критерии успеха») и полей «Проверка» шагов 0–8:

- Регистрация создаёт пользователя строго с ролью `user`, даже если в запросе передано другое значение `role` (Шаг 6).
- Пароль нигде не хранится в открытом виде — только bcryptjs-хеш (Шаг 6).
- Вход создаёт рабочую серверную сессию (`Session` + cookie); выход её инвалидирует (Шаг 6).
- `/account` недоступна без авторизации и показывает данные только владельца сессии (Шаг 7).
- Обращение к административному разделу без роли `admin`/`super_admin` блокируется на сервере, независимо от видимости пункта меню (Шаг 7).
- После запуска seed в БД существует ровно один `super_admin`; повторный запуск seed не создаёт второго (Шаг 4).
- Prisma и `@prisma/client` зафиксированы версией `6.19.3` без диапазонов (Шаг 0, перепроверено на Шаге 4).
- `npm run dev` поднимает проект локально без ошибок (Шаг 0, финально перепроверено на Шаге 8).
- README/runbook содержит фактические, проверенные команды запуска, миграции и seed (Шаг 8).
