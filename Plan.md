## 2. Требования к результату

Сводка из `spec.md` (разделы «Цели», «Функциональные требования», «Критерии успеха»):

- Публичная регистрация создаёт аккаунт строго с ролью `user`; поле `role` из запроса игнорируется сервером.
- Пароль хранится только как bcryptjs-хеш (12 раундов), исходное значение нигде не сохраняется и не логируется.
- Вход по email/паролю создаёт серверную сессию (запись `Session` + cookie); выход инвалидирует сессию.
- Сообщение об ошибке валидации email — точная формулировка «Введите корректный адрес электронной почты».
- Страница `/account` доступна только авторизованному владельцу, показывает профиль, роль и карточки «Быстрые действия», зависящие от роли.
- Серверные проверки роли (`requireRole()`) обязательны для защищённых маршрутов — не полагаться на скрытие UI.
- Навигация показывает все пункты меню всегда, независимо от роли и статуса авторизации.
- Ровно один `super_admin` создаётся seed-скриптом; повторный запуск seed не создаёт дубликат; публичная регистрация не может создать `admin`/`super_admin`.
- Prisma и `@prisma/client` зафиксированы точной версией `6.19.3` (`--save-exact`).
