## 1.1 Целевой сценарий

Путь конечного пользователя данных этого цикла (проверяется без UI — через Server Actions/скрипт локальной проверки, аналогично тому, как auth-lite Шаг 6 проверялся через `curl` до появления полноценного UI):

1. В БД существует доступный `Slot` (создан вручную/через seed для локальной проверки).
2. `user` создаёт `Booking` на этот слот → бронь получает статус `pending`; слот перестаёт быть доступен для новой брони.
3. Владелец брони (`user`) получает `Notification` о создании брони.
4. `admin`/`super_admin` подтверждает бронь (`pending → confirmed`) → владелец получает `Notification` о подтверждении.
5. `admin`/`super_admin` отменяет подтверждённую бронь (`confirmed → cancelled`) → владелец получает `Notification` об отмене; слот снова доступен для новой брони.
6. Повторная попытка создать бронь на уже занятый (`pending`/`confirmed`) слот отклоняется сервером.
7. Попытка `user` отменить или подтвердить чужую бронь отклоняется сервером.
8. Попытка `user` подтвердить свою же бронь (роль `user`, не `admin`) отклоняется сервером.

## 5. Критерии готовности

- `CLAUDE.md` актуализирован шестью ограничениями цикла «слой данных» до начала Шага 1 (Шаг 0).
- Модели `Slot`, `Booking`, `Notification` и enum `BookingStatus` реализованы в `schema.prisma` строго по снимку раздела 2, миграция применена без потери данных auth-lite.
- Три статуса брони (`pending`/`confirmed`/`cancelled`) и ровно три допустимых перехода между ними реализованы и покрыты и позитивной, и негативной проверкой.
- Бронь физически невозможно создать на слот, у которого уже есть активная (`pending`/`confirmed`) бронь — подтверждено проверкой на конкурирующий запрос в рамках Шага 5/6.
- `user` не может изменить статус или прочитать чужую бронь ни при каком запросе — проверка на сервере, не только в UI (UI в этом цикле не создаётся).
- `admin`/`super_admin` не может выполнить действие вне матрицы ролей раздела 4 `spec.md` (например, создать бронь от своего лица как клиент).
- При создании брони и при каждой смене статуса создаётся ровно одна запись `Notification` для владельца брони — подтверждено для всех трёх событий.
- Регрессий в auth-lite нет: `register`/`login`/`logout`/`/account`/`/admin` работают как до начала этого цикла.
- `npm run lint` и `npm run build` проходят без ошибок.
- `README.md` актуализирован, самодостаточен, отражает слой данных фактическими командами и результатами.
