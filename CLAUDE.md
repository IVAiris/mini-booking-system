# CLAUDE.md — mini-booking-system

## 1. Что читать первым
- `spec.md` — источник продуктовой логики текущего шага (auth-lite: роли, сессии, требования, критерии готовности).

- `AGENTS.md` — авто-генерируется `next dev` (блок nextjs-agent-rules); содержит версия-специфичные предупреждения по Next.js 16, не редактировать вручную выше/внутри этого блока.

## 2. Источник продуктовых правил
- Продуктовая логика: `spec.md`. Не дублировать в CLAUDE.md статусы, сущности, критерии готовности — только ссылка.
- Структура проекта: `README.md` пока содержит стандартный шаблон create-next-app, не актуализирован под проект (обновление запланировано на Шаг 8 в `Plan.md`). До этого — не источник истины по структуре.

## 3. Разрешённый стек (по package.json)
Next.js 16.3.1, React 19.2.8, TypeScript, Tailwind CSS 4, Zod, Prisma/@prisma/client — точная версия 6.19.3 (`--save-exact`), bcryptjs, PostgreSQL, npm.

## 4. Инженерные конвенции и что нельзя добавлять без явной задачи
(источник: `spec.md` разделы 3 и 7, `Plan.md` «Правила работы с планом»)

**Устоявшиеся конвенции (соблюдать по умолчанию):**
- Пароль хешируется bcryptjs, 12 раундов; открытый пароль не логируется и не хранится.
- Проверка роли (`requireRole`) и сессии (`getCurrentUser`) выполняется только на сервере (`lib/auth.ts`), не полагаться на скрытие UI-элементов.
- Мутации — через Server Actions (`"use server"`), без middleware (`middleware.ts` для ролей/сессии не используется).
- Session-токен — в cookie, запись в таблице `Session` — источник истины о валидности.

**Нельзя добавлять без явной задачи:**
- Домены слотов, бронирований, уведомлений.
- Middleware-based route protection (`middleware.ts`) для ролей/сессии.
- Сторонние auth-библиотеки (NextAuth.js/Auth.js).
- Изменение зафиксированной версии Prisma (6.19.3) на диапазон или другую версию.
- Разграничение прав `admin` vs `super_admin`.
- Скрытие пунктов навигации по роли.

## 5. Если не хватает контекста
Спросить пользователя точным вопросом, не предполагать и не додумывать формат/scope.

## 6. Проверки после изменений
Автоматических тестов и CI в проекте нет. Актуальный список проверок смотреть в `package.json` → `scripts` (сейчас: `dev`, `build`, `start`, `lint`). При отсутствии проверки под конкретный сценарий — проверять вручную (например, через `npm run dev`).

## 7. Рабочие правила
(источник: `Plan.md` «Правила работы с планом»)
- Работать по одному активному шагу `Plan.md` за раз; не начинать следующий, пока текущий не помечен ✅ или проблема не зафиксирована как принятый риск.
- После завершения шага сразу обновлять его блок в `Plan.md` (Статус, Проверка, Ошибки, Следующий шаг).
